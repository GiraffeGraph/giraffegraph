# data — external labelled data and evaluation sets

Externally labelled hadith data downloaded on 2026-10-12, and the evaluation sets built from it for
the isnad (narrator chain) extraction prototype. The data is used for evaluation only and is not
redistributed. This folder is a private repository; `raw/` and `work/` are not tracked in it.

No set in this folder is a human double-annotated gold standard, and no source describes its labels
as one. Sanadset `<NAR>` labels were generated by regular expressions and text matching. Ifta labels
are the markup of the Ifta' Sunnah platform as scraped and restructured by a third party. A score
against either measures agreement with those labels.

## Layout

| Path | Content |
|---|---|
| `raw/<source>/` | Files exactly as downloaded. `extracted/` subfolders hold the unpacked GitHub archives. Files starting with `_` are saved API responses. |
| `raw_manifest.json` | Size and sha256 of every file under `raw/` (99 files, 4,541,997,359 bytes). |
| `scripts/` | Every script used. Standard library only. |
| `work/` | Intermediate six-book extracts that the builders read (`ifta_sixbooks.jsonl`, `sanadset_sixbooks.jsonl`, and their counts). |
| `eval/<set>/` | The evaluation sets. |
| `cache-and-ledger-backup/` | Copy of the workspace folder `cache-and-ledger/` (essay, tools, verification scripts, the 2026-10-13 experiments and their outputs), which is not a repository of its own. Refresh: `rsync -a --delete --exclude .DS_Store --exclude __pycache__ --exclude .cache-bc5cdr ../cache-and-ledger/ cache-and-ledger-backup/`. |
| `core-backup/` | Copy of two folders that `giraffegraph-core` does not track because they hold third-party text: `evaluation/results/` (full outputs of the experiment runs) and `backend/var/llm-cache/` (stored model responses, which replay the runs without new API calls). Paths mirror the engine repository. |

`raw/` can be downloaded again with the commands under "Sources" and checked against
`raw_manifest.json`; `work/` and `eval/` are rebuilt from it by the scripts.

To refresh `core-backup/` from the engine repository, and to restore it into a fresh clone:

```
rsync -a --delete ../giraffegraph-core/evaluation/results/ core-backup/evaluation/results/
rsync -a --delete ../giraffegraph-core/backend/var/llm-cache/ core-backup/backend/var/llm-cache/
rsync -a core-backup/ ../giraffegraph-core/
```

Downloaded files are untrusted. Nothing from `raw/` is executed (the Ifta GitHub archive contains
Python scripts; they were not run). Scripts are run with `python3 -I` (Python 3.9.6 on the build
machine) from the workspace root with paths as arguments. Re-running the build chain reproduces
every file under `eval/` byte for byte.

## Sources

### 1. Ifta Sunnah Hadith & Narrators data family (Jehad Oumer)

Three Kaggle releases of one corpus, plus the GitHub hub repository. Only the six canonical books
and the narrator catalogue were downloaded, not all 33 books.

| Release | Kaggle slug | Version, last updated (Kaggle API) | Licence field on Kaggle |
|---|---|---|---|
| Original corpus | `jehadoumer/ifta-hadith-corpus-original` | 14, 2026-04-19 | "CC BY-SA 4.0" |
| Graph release | `jehadoumer/ifta-hadith-isnad-linked-graph-data` | 7, 2026-04-19 | "Attribution-NonCommercial-ShareAlike 3.0 IGO (CC BY-NC-SA 3.0 IGO)" |
| Entities and relations | `jehadoumer/ifta-hadith-with-narrators-entities-and-relations` | 5, 2026-04-20 | "Unknown" |

**How downloaded.** No Kaggle credentials were used. Three public endpoints answered HTTP 200:

```
curl -sS -o _kaggle_api_view.json "https://www.kaggle.com/api/v1/datasets/view/jehadoumer/<slug>"
curl -sS -o _kaggle_api_list.json "https://www.kaggle.com/api/v1/datasets/list/jehadoumer/<slug>?pageSize=200"
curl -sS -L --retry 5 -C - -o <file> "https://www.kaggle.com/api/v1/datasets/download/jehadoumer/<slug>/<file>"
```

The per-file endpoint redirects to a signed `storage.googleapis.com` URL. The whole-dataset endpoint
(`.../download/jehadoumer/ifta-hadith-corpus-original`, 9,807,649,446 bytes according to the API)
was not used: a GET on it was stopped after two minutes before curl printed a status, and a HEAD
request on it returned 404. Two files were resumed with `-C -` after an interrupted transfer
(HTTP 206). Every downloaded file has the size the Kaggle file listing gives for it, and every JSON
file parses.

GitHub hub repository, commit `08215403b09590e62cbb7fde1e78de510d19174e` (2026-04-24):

```
curl -sS -L -o Ifta-Sunnah-Hadith-and-Narrators-Dataset-main.zip \
  "https://codeload.github.com/JehadOumer/Ifta-Sunnah-Hadith-and-Narrators-Dataset/zip/refs/heads/main"
```

**Licence and terms, as stated (accessed 2026-10-12).**

- Kaggle licence fields: see the table above. Source: `licenseName` in
  `https://www.kaggle.com/api/v1/datasets/view/jehadoumer/<slug>`, saved as `_kaggle_api_view.json`
  in each release folder.
- README of the original corpus (`raw/ifta-kaggle/corpus-original/README.md`): "This bundle is a
  structured extract only: scholarly authority and usage rules remain with the platform. Attribute
  the program and institution, and follow the platform's terms, notices, and licensing for your use
  case."
- README of the GitHub repository: "Please attribute the source program and follow applicable
  platform terms, notices, and licensing constraints."
- README of the graph release has a section titled "License and citation"; it lists what to cite and
  contains no licence text.
- Not stated: the GitHub repository has no LICENSE file (GitHub API `license: null`). The README of
  the entities release has no licence statement. The terms of the Ifta' Sunnah platform itself
  (`https://sunna.alifta.gov.sa/`) were not retrieved and are not recorded here.

**What the labels are and who produced them, in the source's words.**

- Origin: "a machine-readable JSON export of hadith texts and narrator profiles from the official
  Ifta' Sunnah digital library". "Curation combined manual review of how the website exposes hadith
  text, narrator cards, and metadata with automated crawling and parsing (Scrapy and HTML parsing
  against `sunna.alifta.gov.sa`)." "This is extraction and structuring from an existing scholarly
  source, not new fiqh or hadith authentication work."
- `names` (original corpus): "Surface mentions linked to `narrator_id`", triples
  `[surface, diacriticized_form, narrator_id]`.
- `chain_of_narrators` (graph release): each step is `[narrator_id, display_string]`, "ordered from
  early transmission toward the compiler". The ids were assigned by the curator: "positions were
  aligned to `ifta_narrators.json` where a chain label uniquely identified one catalog row; remaining
  cases used other structured signals on the same hadith ...; a small tail of ambiguous or
  compiler-side figures was settled manually" (emphasis markup of the README removed). Hadiths with
  an unresolved position were dropped. The
  GitHub README says of this release: "it is not part of the thesis".
- Entities release: BIO tags "produced by rule-based span mapping on source text using baseline
  `names` and `narration_words`"; `chain_of_names` is "derived string-based chain structure mapped
  from `chain_of_narrators` + `names`".
- The source does not say how the platform itself produced its narrator markup, and reports no
  inter-annotator agreement.

**Observed in the downloaded files.**

| `sahih-al-bukhari.json` | 7,410 | 7,195 | 4,323 |
| `sahih-muslim.json` | 7,666 | 7,599 | 5,430 |
| `sunan-abi-dawud.json` | 5,260 | 5,082 | 4,533 |

- The entities release states "33 book JSON files (276,347 hadith rows)", and its
  `dataset_manifest.json` lists the original counts (34,995 for these six books). The six files
  hold 27,599 records; every one of them is in the train/val/test id lists. The files contain the
  benchmark-split rows only.
- `ifta_narrators.json` has 20,957 profiles. Ids 0, 1 and 2 are placeholders, not people:
  "[راو لم نهتد إلى تعيينه]", "[راو لم نقف له على ترجمة]", "[راو موضع إبهام]".
- `hadith_num` repeats inside a book (Muslim: 6,548 of 7,666 records share a number with another
  record), so it cannot serve as an id. `mainId` is unique.
- `hadith_text_diac` carries edition apparatus: page markers (`[1/220]`), print numbers (`15 - `,
  `99 (م) - `, `2953 (م 1) - `, `6 / 1 - `, `( 48 )`), line breaks, and for the first hadith of a chapter the chapter
  title in front of the hadith. A small number of records end with a modern editor's note.

### 2. AR-Sanad 280K (`somaia02/Narrator-Disambiguation`)

Commit `ddde1960dd4af1e50ecbe36ff5b92dee0c48bcf4` (2025-02-22).

```
curl -sS -L -o Narrator-Disambiguation-main.zip \
  "https://codeload.github.com/somaia02/Narrator-Disambiguation/zip/refs/heads/main"
```

**Licence and terms, as stated (accessed 2026-10-12).** The repository has no LICENSE file (GitHub
API `license: null`) and its README contains no licence or terms statement. The v1 paper (Mahmoud
et al., *Information* 13(2):55, DOI 10.3390/info13020055) is listed by Crossref with licence URL
`https://creativecommons.org/licenses/by/4.0/`; that statement is the article's, saved as
`raw/ar-sanad-paper/crossref_10.3390_info13020055.json`. The repository does not say whether it
extends to the data files.

**What the labels are, in the source's words.** The README describes 279,625 artificial sanads for
training and validation covering 18,298 narrators, and continues: "It also has a test set of 27,056
real sanads from the 6 most famous hadith books." "Narrators' information include: Full names,
namings (appearance forms), Shuhra, Rank by Ibn Hajar, Birth date, etc." The
README does not say how the narrator ids of the test chains were assigned. The test file gives
narrator names already separated; it has no hadith text.

  It names the origin: "Original Source: Mendeley Data" (`https://data.mendeley.com/datasets/5xth87zwb5/5`).
- Mendeley Data record of that original deposit (DOI 10.17632/5xth87zwb5.5), licence field:
  "CC BY 4.0", "Creative Commons Attribution 4.0 International", with the text "You can share, copy
  and modify this dataset so long as you give appropriate credit, provide a link to the CC BY
  license, and indicate if changes were made, but you may not do so in a way that suggests the
  rights holder has endorsed you or your use of the dataset. Note that further permission may be

  Saved as `raw/sanadset-paper/mendeley_api.json`
  (`https://data.mendeley.com/public-api/datasets/5xth87zwb5?version=5`).
- Paper (Mghari, Bouras, El Hibaoui, *Data in Brief* 42, 2022, DOI 10.1016/j.dib.2022.108540): "This
  is an open access article under the CC BY license (http://creativecommons.org/licenses/by/4.0/)."
  Full text saved from Europe PMC (PMC9440281).

**What the labels are and who produced them, in the source's words (paper, section 2.1).** "We used
data web scrapping technics to collect Hadith data from trusted websites." "After collecting the
data, we further processed the raw Hadith text field and separate its components with the help of
regular expressions and text matching technics". "Every narrator in the Sanad is tagged with <NAR>
tag." "We found the in some cases hadith writers used words like: , to identify ambiguous names. We
used <IDF> to tag those." The websites are not named.

**Observed.** `train/sanadset.csv` has 650,986 rows and six columns (`Hadith`, `Book`,
`Num_hadith`, `Matn`, `Sanad`, `Sanad_Length`). It has 956 distinct `Book` values; the card says
926 books. Six-book rows: صحيح البخاري 6,977, صحيح مسلم 5,348, سنن أبي داود 4,569, جامع الترمذي
3,814, سنن النسائى الصغرى 5,668, سنن ابن ماجه 4,336. In the record inspected (Muslim 978) the
`Sanad` column lists the narrators in an order that is not text order. The builders take the `<NAR>`
spans from the `Hadith` column in text order, which reproduces the pilot sample's `raw` and
`ref_nars` (tags stripped) for all 50 pilot hadiths.

Text matching between corpora (`common.py`): both texts are normalised (diacritics and tatweel
removed, alef forms folded, ى→ي, ة→ه, punctuation and digits removed, spaces collapsed). `ratio` is
2·M/(len a + len b) with M the characters in `difflib.SequenceMatcher` matching blocks.
`containment` is the characters in matching blocks of at least 20 characters divided by the shorter
length. Both are computed for the candidates of the same collection that are closest by token set:
the 8 with the highest Jaccard overlap and the 8 with the highest token containment (25 and 25 for
the pilot exclusion).

### A. `eval/sixbooks-fresh/` — extraction test set, Ifta labels

300 hadiths, 50 from each of Bukhari, Muslim, AbuDawud, Tirmidhi, Nasai, IbnMajah; 1,778 reference
mentions.

| File | Content |
|---|---|
| `hadiths.json` | `{"coll", "num", "raw"}`. `num` is `ifta-<mainId>`. |
| `reference.jsonl` | Scorer format. Every labelled mention once, in text order. |
| `reference_chains.jsonl` | `chains` (one list per chain), `narrator_ids` (aligned), `mentions_outside_chains`, `narrator_ids_outside_chains`. |
| `reference_sanadset.jsonl` | Set B, see below. |
| `provenance.json` | Source files with sha256, rules, seed, counts per collection, pilot exclusions, one entry per hadith (`ifta_main_id`, print number, cleaning applied, removed chapter title, benchmark split). |
| `label_checks.json`, `spotcheck.md` | Label sanity report and 10 hadiths printed with their labels. |
| `sanadset_matches.json` | Set B link per hadith. |

**Fields.** `raw` is `hadith_text_diac` of the original corpus, cleaned. Mentions are the
diacritised surface forms in `names`, in list order, with the same cleaning and punctuation
stripped from both ends. Chains come from `chain_of_narrators` of the graph release.

**Cleaning of `raw`** (number of the 300 hadiths each rule changed): print numbers removed (296);
line breaks and whitespace runs collapsed (122); chapter title in front of the hadith's print number
cut off (111; the removed title is kept in `provenance.json`); page markers removed (105); a dash
left at the start of an unnumbered record removed (3). Nothing else is changed: diacritics,
punctuation, `( ح )` markers and Quran braces `{ }` stay.

**Eligibility and sampling.** At least 2 labelled mentions; cleaned text 100–3000 characters; record
present in the graph release with at least one chain; not matching a pilot hadith. Pilot exclusion
is wider than the 0.9 used for linking: any Ifta record with ratio ≥ 0.8 or containment ≥ 0.8
against a pilot hadith of the same collection is removed (68 records; each of the 50 pilot hadiths
has at least one). Draw: `random.Random("20261012:<coll>").sample(eligible sorted by mainId, 50)`.

| Collection | Records | ≥ 2 mentions | Length in range | In graph release | Matching a pilot hadith | Eligible | Drawn |
|---|---:|---:|---:|---:|---:|---:|---:|
| Bukhari | 7,410 | 7,199 | 7,324 | 7,195 | 0 | 7,093 | 50 |
| Muslim | 7,666 | 7,640 | 7,615 | 7,599 | 20 | 7,531 | 50 |
| AbuDawud | 5,260 | 5,252 | 5,245 | 5,082 | 13 | 5,055 | 50 |
| Tirmidhi | 4,412 | 4,313 | 4,389 | 4,231 | 12 | 4,176 | 50 |
| Nasai | 5,780 | 5,773 | 5,770 | 5,696 | 11 | 5,675 | 50 |
| IbnMajah | 4,467 | 4,466 | 4,463 | 4,438 | 12 | 4,421 | 50 |

The middle columns are counted independently on all records; "Eligible" is their intersection minus
the pilot matches.

**Reference conventions.**

- `reference.jsonl` is in text order with each written mention once. Parallel chains written one
  after another come out chain by chain; a narrator shared by several chains but written once
  appears once. This is how the system export orders mentions (by text position).
- `reference_chains.jsonl` lists each chain compiler side first, the order an isnad is written in
  (the graph release stores the reverse). A chain step is mapped to the occurrence of its narrator
  id in `names` that keeps the chain in text order. A mention shared by several chains appears in
  each of them.
- Chain steps with no mention in the text are left out: the compiler in 385 of 394 chains, and 33
  other steps, which belong to abbreviated records ("... عن الأعمش بهذا الإسناد").

**Label sanity (`label_checks.json`).**

| Check | Value |
|---|---|
| Reference mentions found verbatim in `raw` after normalisation | 1,778 of 1,778 (1.000) |
| Hadiths whose mentions are all found in text order | 300 of 300 |
| Mentions per hadith | min 2, median 6, mean 5.927, max 11 |
| Hadiths with more than one chain | 74 of 300 (0.2467); chains per hadith: 1 → 226, 2 → 60, 3 → 10, 4 → 3, 6 → 1 |
| Mentions outside every chain | 15, in 11 hadiths |
| Mentions of the compiler himself ("قال أبو داود") | 10, in 9 hadiths |
| Mentions with a placeholder narrator id | 1 |
| Chain steps mapped out of text order | 8 |

The verbatim figure is expected to be 1.0: the mentions are the platform's own spans of the same
text. It shows the cleaning did not break them; it says nothing about whether the spans are right.

**Caveats.**

- The labels are platform markup, restructured by a third party. Not a gold standard.
- Narrators named in a compiler's comment or follow-up note are labelled inconsistently. In
  Bukhari `mainId` 2457 ("تابعه أبو قلابة وحميد وثابت عن أنس") two of the three names are labelled;
  in AbuDawud `mainId` 94310 none of the four names in the comment is. A system that extracts them
  is counted wrong.
- Some mention spans include a clarification ("يَحْيَى ، هُوَ ابْنُ سَعِيدٍ"; 10 mentions contain
  inner punctuation) and some carry the attached conjunction ("وَقُتَيْبَةُ بْنُ سَعِيدٍ"), as in
  the source.
- 6 of the 300 texts end with a modern editor's note that the cleaning does not remove (found by
  searching for "طبعة"): Bukhari:ifta-2403, AbuDawud:ifta-92839, Nasai:ifta-64223,
  Nasai:ifta-66352, Nasai:ifta-65685, Nasai:ifta-70941. Some of the notes contain narrator names.
- The chapter-title cut relies on the hadith's print number standing between title and hadith. In
  the six books, 32 records with at least 2 mentions still start with باب/كتاب/أبواب after
  cleaning; none of them is in the sample.
- Requiring the graph release removes records whose chain ids the curator could not resolve
  (754 of 34,995 six-book records are absent from it).
- 254 of the 300 are also in the entities release (train 181, val 35, test 38). Anyone evaluating
  the models trained on that release must use the 38 test hadiths or exclude the 181.
- For those 254, the per-chain mentions equal the release's own `chain_of_names` in 246. In the
  other 8 a narrator is written twice and `chain_of_names` takes the later mention.
